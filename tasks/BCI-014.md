# BCI-014 - UI-11: Ask BCION shell, deterministic first, no input element

Model tier: standard
Wave: P1a (wave 2) - Phase 1a runs alongside Phase 1; this card touches no Phase 1 template
Worktree: phase1a/ui-11-ask-shell

## What to build
`GET /ask?template=<id>&pathway_id=<uuid>` (and `&career_id=<uuid>` as an alternative to `pathway_id`) as a JSON route in `app/api/ask.py` (new) and a zero-JS server-rendered page in `app/web/ask_pages.py` (new) + `app/web/templates/ask.html` (new). This card runs **in deterministic mode only** - do not import or wait for `app/ai/pipeline.py` (a later card, AI-6, not built yet) or `app/ai/retrieval.py` (AI-5, being built in parallel right now, do not depend on it merging first). Instead call `app.planning.comparison.field_value_for` directly against published claims for the given pathway/career, exactly the way existing pages like `compare.html`'s backing route already do - read that route for the pattern.

Every response renders: the fixed prompt link(s) for the given `template_id` (a small hardcoded registry in this card - `cost_breakdown`, `pathway_overview`, `eligibility_gap`, matching the three existing `_ask.html` call sites), server-rendered fact cards using the existing `_trust_badge.html` macro, citation links built only from the retrieved records (never a raw student-supplied URL), a missing-information list, and when there is nothing to show or the AI flag is off, the **exact** copy from `docs/UI.md`: "You can still compare routes and use the calculators." Read `app/core/config.py`'s `AI_ENABLED`/`ai_configured` (do not add a new flag) - when either is false, or when this card's deterministic lookup finds nothing published, render that exact fallback copy plus whatever fact cards ARE available, never an error page.

Fill the body of `app/web/templates/_ask.html`'s `ask_bcion` macro (currently an empty stub) so the three existing call sites - two in `compare.html`, one in `requirements.html` - render a working link to `/ask?template=...` in every mode. **Do not edit `compare.html`, `requirements.html`, or any other journey template** - only `_ask.html` itself, which is already on the "one open task per macro" list as yours per its own header comment.

An unknown `template_id` returns a friendly 404-style page, not a 500, and never reflects the raw unknown id back into the response body (avoid any reflected-value surface). No `<input>`, `<textarea>`, or `contenteditable` element anywhere in `ask.html` - write a grep-based test that asserts this mechanically, not just by inspection.

The route needs to be registered - you cannot edit `app/main.py` yourself (it is a frozen registry, lead-only for a new router slot). Instead, build `app/api/ask.py`'s router object (e.g. `ask_router`) ready to be added as a `RouterSlot`, and give the lead the exact one-line addition needed (both the import line and the `RouterSlot("ask", ask_router)` line) in your completion report.
