# BCI-006 — First UI slice: Explore → Compare

**Milestone:** M2/UI (Lite Build Pack §5 Interface brief) · **Status:**
DONE — the first real, clickable screens this whole project has had.
Every route before this task returned JSON only.

## Scope
docs/UI.md's "Career explorer" and "Comparison screen" (the two already
fully-built, fully-tested JSON endpoints — `GET /careers`, `GET
/compare` — get an actual human interface on top of them). Chosen as the
first slice because it's the part of the "one journey" (explore → compare
→ calculate → see requirements → save) that was already engineering-
complete and needed nothing new from the data/rules layers.

## Why this, now
Every milestone through M4 (eligibility, cost, timeline engines; sign-in;
saved plans; maker-checker; the publishing console) shipped as JSON API
routes only. Nobody — student or reviewer — could actually click through
any of it. This is arguably the biggest gap in the whole project relative
to its own mission: a pilot students can use, not just an API surface.

## What shipped (2026-09-19)
- **Tailwind, wired as a dev-time build tool only** (`package.json`,
  `tailwind.config.js`, `app/web/styles/input.css` →
  `app/static/css/app.css` via `make css`/npx). Node/npm sit at the same
  tier as ruff/mypy — a local dev dependency; the compiled CSS is
  checked in, so nothing at runtime or in the eventual Docker image needs
  Node at all (docs/ARCHITECTURE.md updated to say so explicitly).
  Design tokens (colors, font stack) implement docs/UI.md's "Visual
  direction" and "Typography" sections line-for-line — warm white /
  deep charcoal / one deep-blue accent / teal-green positive / amber
  caution / red-sparingly; Noto Sans via system fonts only, so "no
  web-font download in text-only/2G mode" holds without special-casing.
- **`app/api/compare.py` refactored first, before any template existed**:
  extracted `assemble_comparisons()` (the actual fetch-claims +
  assemble-trust-labels + compute-cost logic) out of the JSON route
  handler into a plain function returning a `PathwayComparisonData`
  dataclass. Both the existing JSON route and the new HTML page below
  call this SAME function — one code path for the safety-critical trust-
  labelling and cost arithmetic, not two chances to get it wrong.
  Verified zero behavior change: the full existing
  `tests/db/test_api_explore_compare.py` suite re-run and passing
  unchanged before building anything on top of it.
- **`app/web/pages.py`**: `GET /explore`, `GET /compare/view`, `GET /` →
  redirect. Deliberately distinct paths from the JSON API's `/careers`
  and `/compare` (not content negotiation on the same URL) — keeps the
  already-tested JSON contract completely untouched.
  - `/explore`: careers grouped with their pathways, a checkbox per
    pathway, plain `<form method="get">` submitting straight to
    `/compare/view` — the core flow works with **zero JavaScript**
    (docs/UI.md "Weak connection: lightweight content" — the journey
    must not depend on a script loading). A small script only adds a
    live "N of 3 selected" count and disables further checkboxes past 3;
    without it, `/compare/view` itself still rejects anything outside
    2-3 with a clear message, so nothing actually depends on the script.
  - `/compare/view`: renders `PathwayComparisonData` per pathway —
    entry requirements, main stages, time, location, and the cost
    section (verified charges / estimated extras / potential assistance
    / "what you'd need to arrange", **kept as four visually distinct
    numbers, never merged** — docs/UI.md "Timeline & cost"). Every field
    shows its trust badge with **text + icon, never colour alone**
    (docs/UI.md "Visual direction"), matching exactly the five labels in
    docs/UI.md's trust-labels table. Closing prompt is docs/UI.md's exact
    required line: "Which option would you like to investigate further?"
    A wrong pathway count renders a friendly in-page message with a link
    back to Explore, not the JSON API's bare 400 (docs/UI.md "difficult
    states": explain, don't just error — a human clicked into this page,
    they didn't send a malformed request on purpose).
- **6 new live tests** (`tests/db/test_web_pages.py`): home redirect,
  static CSS actually served, explore lists a real seeded
  career/pathway, wrong pathway count shows the friendly message, the
  full compare render shows both pathway names + the correct trust badge
  + the formatted cost figure + "Not available" for a pathway with no
  claims at all, and the closing prompt is present verbatim.
- Verified live end-to-end by hand first (seed real data, hit both pages,
  read the actual rendered HTML) before writing the permanent tests —
  same discipline as every other live-DB test in this repo.

## ux-qa-reviewer's first-ever review, and the fixes that followed (2026-09-19)
Invoked immediately after the slice above shipped — the first time this
project has had a "journey to actually click through" for that agent's
own trigger condition to be met. It walked every scenario (0/1/2/4
pathways, malformed and nonexistent ids, zero-claims pathways, an XSS
probe) live against real seeded data. Findings, and what was fixed:

- **Fixed — highest severity**: a malformed `pathway_id` (not
  UUID-shaped — a very plausible outcome of a truncated/garbled shared
  link, and this product's sharing channel is WhatsApp) reached Postgres
  raw and crashed to a bare, unstyled 500 with no way back, directly
  contradicting `compare_page`'s own docstring. Fixed with a shape check
  before any query runs, same friendly message as the wrong-count case.
- **Fixed**: every evidence link said "Official source" regardless of
  the field's actual trust label — an `institution_reported` or
  `needs_rechecking` field showed a badge saying "not independently
  confirmed"/"verification overdue" directly beside a link claiming to
  be official, contradicting the badge on the same line. `FieldValue`
  (`app/planning/comparison.py`) gained an additive `source_authority`
  field (also added to the JSON API's `FieldValueOut`, non-breaking);
  the link now names the actual source and qualifies non-official
  labels.
- **Fixed**: the comparison grid used an inline `grid-template-columns`
  style with no responsive override at all — 2-3 columns crammed into
  strips on a phone instead of stacking, failing docs/UI.md's mobile
  requirement by a different mechanism than the literal sideways-scroll
  it explicitly bans. Replaced with literal `grid-cols-1 md:grid-cols-2`
  / `md:grid-cols-3` classes (must be literal, not interpolated, for
  Tailwind's content scanner to keep them).
- **Fixed**: field order didn't match docs/UI.md's spec (Location was
  rendered before Cost; the spec has it after). Reordered.
- **Fixed**: money fields rendered as bare numbers (`125000`) or with a
  stray trailing `.0` (`30000.0`) while only `net_to_arrange` got real
  currency formatting — undercutting "explain verified-cost vs estimate"
  by making the other three amounts not obviously read as money at all.
  All cost figures now use the same ₹ + thousands-separator formatting.
- **Fixed**: a pathway with no hint claim showed "0.0" for estimated
  additional expenses with no distinction from a genuinely-known zero —
  risked reading as "this costs nothing extra" for a pathway the system
  actually knows nothing about. Added an explicit note when the value is
  the assumed-zero default.
- **Fixed**: nonexistent-but-valid-UUID pathway fell back to showing the
  raw UUID as the comparison card's heading. Now shows "This pathway".
- **Fixed**: `text-neutral` on `bg-neutral-bg` measured ~4.4:1 contrast,
  just under WCAG AA's 4.5:1 for normal text (worse on the italicised
  "Estimate" badge). Darkened the neutral color token.
- **Fixed**: checkbox tap targets on Explore were 16×16px, well under
  the ~44px guidance. The whole row is now one `<label>` with padding
  and a `min-h-11` (44px) guarantee, not just "probably tall enough"
  from two lines of text.
- **Fixed**: `target="_blank"` evidence links had no accessible
  indication of opening a new tab. Added a screen-reader-only note.
- **9 new regression tests** across `tests/db/test_web_pages.py` (3) and
  `tests/unit/test_comparison.py` (2), plus the existing suite re-run to
  confirm zero regression.
- **Not fixed, explicitly deferred**: "Report an issue" per-field
  (docs/UI.md requires it; no reporting mechanism/backend exists yet —
  adding a link that goes nowhere would be worse than the current gap);
  a real distinction between "assumed zero" and "confirmed zero" at the
  data-model level (the note added is a mitigation, not a fix — would
  need `ProgrammeCostBreakdown` to carry a has-hint flag, a shared-logic
  change touched with more care than a same-day UI-review fix pass
  warrants); Playwright e2e (unchanged from before this review — see
  below); a genuine mobile-viewport screenshot/visual check (the fix
  above is verified by class presence, not by looking at a rendered
  phone-width page).
- Verified all fixes live against real seeded data (including the
  malformed-UUID crash, confirmed reproduced then confirmed fixed) before
  writing permanent tests, same discipline as the rest of this repo.

## Not done yet (this task's remaining scope)
- **Playwright e2e is still not wired** (`make test-e2e` says so
  honestly rather than the old, now-stale "no UI to drive" message).
  `tests/db/test_web_pages.py` covers the same journey via FastAPI's
  `TestClient` (fast, no browser) in the meantime — real browser
  rendering, JS behavior (the "3 selected" cap), and actual mobile
  viewport layout are NOT verified by anything yet.
- **No mobile-viewport verification** — the CSS grid is written to
  collapse per docs/UI.md's "stacked sections, never a sideways-
  scrolling table" rule, but nothing has actually rendered it at a phone
  width and looked.
- **No other screens** — quick start, timeline/cost calculator (the
  `POST /timeline` and eligibility APIs both exist and are fully tested,
  neither has a page), exam/programme detail, My Plan, Ask BCION, the
  reviewer console (the publishing-console API from BCI-005 exists,
  nothing shows it to a human yet). Explore→Compare was chosen as the
  first slice specifically because those two APIs were already complete;
  the rest need their own bounded tasks.
- **No usability round** — docs/UI.md calls for 5-8 participants
  (including a shared-phone user, a Hindi-preferring user, a parent, a
  teacher) before the comparison/cost engines are considered UI-complete.
  Nothing here substitutes for that.
- **English only** — no Hindi/Gujarati content or translation keys yet,
  despite the font stack already supporting those scripts.
- **Recurring test flakiness noticed, not fixed**:
  `test_sign_up_new_email_succeeds_or_requires_confirmation`
  (`tests/db/test_api_auth.py`) has now failed twice under the full
  combined suite's load and passed both times in isolation — plausibly
  Supabase Auth rate-limiting real sign-ups across this repo's growing
  test count in one run. Second occurrence means it's a real pattern,
  not a one-off; worth a proper fix (retry/backoff, or spacing out
  sign-up-heavy tests) rather than continuing to just note it.
