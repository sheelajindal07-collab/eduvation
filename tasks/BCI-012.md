## What to build
`app/ai/schemas.py` already exists on `main` (merged) - import from it, never redefine anything in it. It exports: `AIAnswerStatus` (six values), `AskRequest`, `Answer`, `PromptTemplate`/`PromptTemplateRequirement`/`PromptTemplateRegistry`, typed errors `AIProviderError`, `AIProviderTimeout`, `AIProviderQuota`, `AIProviderMalformed`, `AINotConfigured` (all in `app/ai/schemas.py`), `OutboundPayload` (frozen, `extra="forbid"`, `record_values` keys must be `<record_id>.<field_name>`), `BANNED_PHRASES`, `find_banned_phrases()`, `SUPPORTED_LANGS`, `MAX_RECORD_IDS`, `MAX_RECORD_VALUE_CHARS`, `MAX_ID_CHARS`.

Harden `app/ai/gemini_provider.py` (already exists, do not rewrite it wholesale - extend it): disable the SDK's own retry behaviour (`http_options` retry count 0, or the equivalent current `google-genai` option - check the installed `google-genai==2.24.0` API surface, it may differ from an older assumption); on any transport/API failure, catch it and raise the matching typed error from `app/ai/schemas.py` (`AIProviderTimeout` for a timeout, `AIProviderQuota` for a 429/quota/rate-limit response, `AIProviderMalformed` for an empty or unparseable response, `AIProviderError` for anything else) - never let the SDK's own raw exception type escape this module; confirm the API key string can never appear in a log line or an exception's string representation (write a test that deliberately triggers each error path and asserts the key isn't in the captured output). Plain-text response mode (the two-pass selection/verification format from later cards is line-based, not JSON) - if `google-genai` defaults to something else, set whatever config disables it.

Extend `app/ai/adapter.py`'s `AIProvider` protocol only if needed to fit the typed errors above - check it first; it may already be compatible.

Extend `app/ai/mock_provider.py`'s `MockAIProvider`: add a way to script a *sequence* of responses across multiple `.generate()` calls (a later card's two-pass pipeline calls `.generate()` twice per answer - selection then verification - and needs to control each call's response independently), and a `raise_on_call(n, error)` hook so a test can make the Nth call raise a specific typed error rather than return text. Keep the existing single-`canned_response`/echo behaviour working unchanged for every existing test that already uses it.
