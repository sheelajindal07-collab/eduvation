## Scope (Lite Build Pack §9, Step 8)
"Managed auth, sessions, guest migration, saved and versioned plans,
export and deletion, consent gate and safeguarding workflow, distress
rule, support queue." Gate: "Consent workflow reviewed by a person."

## Why this, now
M2's three engines (eligibility, cost, timeline) are built and wired
into live routes, but every response today is anonymous and throwaway —
nothing persists across requests. M3 is what turns "a calculator" into
"a plan a student can come back to." It's also what finally gives
`confirmed_assistance` (cost engine) somewhere real to read from — a
student's actual awarded scholarships are account data that doesn't
exist yet.

## Scope for this task (a first slice, not all of M3 at once)
1. **Guest sessions** (docs/UI.md, docs/DATA.md): anonymous server
   session, random token, no personal fields, 7-day expiry, "not saved
   to an account." This is what every unauthenticated request already
   implicitly is today (RLS treats it as `guest`) — this task makes it
   an explicit, trackable session rather than pure statelessness.
2. **Supabase Auth wiring**: sign-up/sign-in using Supabase's own auth
   (already the RLS foundation — `auth.users`, `auth.uid()` are used
   throughout `db/migrations/0001_init.sql`). `app/db/client.py`
   already has `get_user_scoped_client(access_token)`; this task is
   mostly about the sign-in/sign-up HTTP surface and session handling on
   top of what already exists.
3. **Saved plans**: a new table (`saved_plans` — Lite Build Pack §6
   lists it under "Student work"), strictly own-row RLS matching
   `student_profiles`' existing pattern. A plan references a pathway
   plus the student's chosen assumptions (the same `estimated_additional_expenses`
   override `/compare` already accepts, now persisted instead of
   per-request).
4. **Consent gate — explicitly NOT full safeguarding this task**: per
   `docs/SECURITY.md`, real minor accounts stay disabled until the
   consent and safeguarding workflow is built AND reviewed by a person.
   This task builds the guest → account migration plumbing and the
   schema for consent records, but does not enable real under-18
   sign-up. That flip is a deliberate, separate, gated decision — not
   something this task or any single commit unilaterally turns on.
5. **NOT in this task**: the distress keyword rule and support queue
   (needs the AI/messaging surface, closer to M5), export/deletion
   endpoints (needs a data-retention policy decision first), guardian
   token verification (needs docs/SECURITY.md's DigiLocker/
   school-mediated route to be a real integration, not just a design).

## What shipped (2026-09-19)
- `app/api/auth.py`: `POST /auth/sign-up`, `POST /auth/sign-in`. Never
  distinguishes "wrong password" from "no such account"; sign-up
  returns the same ambiguous response for a brand-new email and an
  already-registered, confirmed one (Supabase's own anti-enumeration
  design — embraced, not fought).
- `db/migrations/0002_saved_plans.sql`: `saved_plans`, RLS identical to
  `student_profiles`'s pattern. `updated_at` kept honest via a trigger.
- `app/api/plans.py`: `POST/GET/PATCH/DELETE /plans`, all behind a new
  `require_auth` dependency (401 for a guest — there's nothing to save).
  A duplicate `(student, pathway)` save is a clean 409, not a raw 500.
- **Two real bugs found and fixed, not assumed away:**
  1. **Security**: `app/db/client.py`'s client factory was a shared
     `@lru_cache`d singleton, and the user-scoping function mutated
     *that same object's* auth token — a genuine cross-user leak risk
     under concurrent requests. Fixed: every call now constructs a
     fresh, unshared client. See `docs/DECISIONS.md` for the full
     writeup; this affected every route already shipped, not just the
     new ones.
  2. `client.auth.get_user()` needs the token passed explicitly
     (`jwt=token`) — it can't find a session on a client that only ever
     had its postgrest layer authenticated. Fixed via a small
     `AuthedSession` dataclass carrying the client and its raw token
     together.
- Also fixed: `email-validator` was a missing dependency (only surfaced
  once a route actually used `EmailStr`), and a real test-data bug —
  `.invalid`-TLD emails are correctly rejected by RFC 2606 (unlike
  `.invalid`'s fine-for-URLs use elsewhere), fixed by using
  `example.com` in test fixtures.
- **13 new tests**: 6 for auth (`tests/db/test_api_auth.py`), 7 for
  plans (`tests/db/test_api_plans.py`). A first attempt put the skip
  hook inside the test file itself, which pytest silently never picks up
  (hooks only live in `conftest.py`/plugins) — caught by actually
  running it, moved to `conftest.py`, reverified.
- **Migration applied, all 7 re-verified live (2026-09-19)**: owner
  applied `0002_saved_plans.sql` via the SQL Editor. Re-ran the suite:
  all 7 pass for real, including `test_student_b_does_not_see_student_a_plan`
  and `test_student_b_cannot_update_student_a_plan` — cross-student
  isolation proven through the actual running API, not just the
  migration's RLS policy in isolation.
- **126 tests passing repo-wide, zero skipped** (92 unit + 34 live DB),
  lint/typecheck clean, CI green.
