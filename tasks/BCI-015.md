# BCI-015 - AI-6: Two-pass pipeline (selection + verification), prompts, guards

Model tier: strongest
Wave: P1a (wave 3) - Phase 1a runs alongside Phase 1; this card touches no Phase 1 file
Worktree: phase1a/ai-6-pipeline

## What to build
`app/ai/pipeline.py` (new): the orchestration function `answer(db, request: AskRequest, provider: AIProvider, budget: AIRequestBudget, *, as_of: date | None = None) -> Answer` (exact signature is your call, but it must take an injectable `AIProvider` and an injectable budget object, never construct its own `GeminiProvider` internally, so tests never touch the network). Steps, in order, matching CLAUDE.md's non-negotiables and this pilot's core rule ("answer or refuse, never guess"):

1. Validate `request.template_id` against a small fixed template registry you define in `app/ai/prompts.py` (new) - `cost_breakdown`, `pathway_overview`, `eligibility_gap` - each naming which of `pathway_id`/`career_id`/`claim_id`/`plan_id` it requires. An unknown template returns `Answer(status=AIAnswerStatus.unsupported_template, ...)` before anything else runs.
2. Check `Settings.ai_enabled` and `Settings.ai_configured` (`app/core/config.py`, read-only for you - do not edit it). Either false returns `Answer(status=AIAnswerStatus.ai_unavailable, ...)` before any retrieval or budget reservation.
3. Retrieve records via `app.ai.retrieval`'s `fetch_pathway_records` / `fetch_career_records` / `fetch_claim_record` (already merged - read `app/ai/retrieval.py` directly for the real signatures and the `RetrievedRecord` shape, do not guess). No records -> `Answer(status=AIAnswerStatus.not_available, ...)`, and the provider is never called (nothing to spend the budget on).
4. Reserve exactly **two** calls from `budget` (the injected `AIRequestBudget`-shaped object - use `app/ai/budget.py`'s existing interface; do not wait for or import `app/ai/budget_db.py`, that card is still blocked and this pipeline must work against the in-memory budget unchanged). A reservation failure returns `Answer(status=AIAnswerStatus.budget_exhausted, ...)` before any provider call.
5. Build the **selection prompt** in `app/ai/prompts.py`: the retrieved records wrapped explicitly as untrusted data (a clear delimiter/label around each record's value, matching the pattern `app/ai/grounding.py`'s `_build_prompt` already uses - read that function directly, reuse its shape rather than inventing a new one), instructing the model to return one bare `[<record_id>]` line per applicable record or the literal `NOT_GROUNDED` and nothing else. Before sending, run `app.ai.schemas.OutboundPayload.from_records(...)` (already merged) and its `untraceable_values` check - if anything is untraceable, that is a bug in this pipeline's own prompt construction, not a runtime student input (there is no student free text in Phase 1a - Rule 3), so raise loudly in a test rather than silently drop.
6. Send the selection prompt via `provider.generate(...)`. Any typed error from `app/ai/schemas.py` (`AIProviderTimeout`, `AIProviderQuota`, `AIProviderMalformed`, `AIProviderError`) caught here settles the budget as failed and returns the deterministic fallback (fact cards from step 3's retrieved records, `status=ai_unavailable`) - never raw model prose, never an exception escaping to the caller.
7. Validate the selection response with the same whole-response, all-or-nothing rules `app/ai/grounding.py`'s `_parse_and_validate` already implements (reuse that logic - either call it directly if its shape fits, or extract the validation into a shared helper both modules import; do not write a second, subtly different regex/parser). Reject if any line isn't an exact `[<record_id>]` match, or any id wasn't in the retrieved set.
8. Build the **verification prompt**: a different, adversarial framing over only the ids the selection pass returned - "for each of these ids, does the record directly answer the question: `YES <id>` or `NO <id>`, one per line, nothing else." Send it via a second `provider.generate(...)` call. Any provider error here also settles the budget as failed and falls back to deterministic fact cards.
9. Validate the verification response with the same strict line-format rule (`YES <id>` / `NO <id>`, exact match, ids must be a subset of what pass 1 selected). Anything outside that format invalidates the *whole* response -> `insufficient_information`. The final id set is the intersection: only ids that were selected in pass 1 **and** confirmed `YES` in pass 2. If that intersection is empty, `Answer(status=AIAnswerStatus.insufficient_information, ...)` with the deterministic fact cards still attached (never a bare refusal with nothing useful).
10. Freshness: any surviving id backed by a stale record (per `RetrievedRecord.is_stale`, or by re-deriving with `app/ai/grounding.py`'s `DEFAULT_FRESHNESS_SLA_DAYS`/comparison pattern if `retrieval.py` doesn't already flag it - check first) downgrades the *whole* answer to `insufficient_information`, same all-or-nothing rule `grounding.py` already documents for this case.
11. For every surviving id, generate the sentence **from the retrieved record's own fields, in code** - reuse `app/ai/grounding.py`'s `_fact_sentence`/`_citation_for` pattern (extract to a shared helper if the private-name boundary is awkward; do not duplicate the template strings). There is no code path by which a character the provider wrote reaches `Answer.sentences` - this is the one property most worth a dedicated test, mirroring `grounding.py`'s own `test_answered_response_text_is_generated_entirely_by_code_never_by_the_provider`.
12. Run `app.ai.schemas.find_banned_phrases()` over every string this pipeline is about to render (the fixed prompt label for the template, the missing-information list, the next-actions list, if any) - not over model output (there is none reaching `.sentences`), but as a build-time/test-time guard against a future card accidentally introducing hedge language into a fixed string. A hit here is a test failure, not a runtime path.
13. Settle the budget with both id lists (`selection_ids`, `verification_ids`) via `budget`'s settle method - no prompt text, no answer text, ever recorded anywhere.

Every failure path (unknown template, AI off, no records, budget exhausted, provider timeout/quota/malformed/error on either call, selection-format violation, verification-format violation, empty intersection, stale) must still return a usable `Answer` with whatever deterministic fact cards retrieval found - **never raise an unhandled exception out of `answer()`**, and never render model-authored free text under any circumstance.
