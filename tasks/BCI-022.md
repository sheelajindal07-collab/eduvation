## What to build
`app/planning/claim_diff.py` (new): a pure function computing the field-by-field diff between a `superseded` claim and its `superseded_by` successor - both rows already exist and are readable (`app/api/claims.py`'s `supersede_claim`/`superseded_by` pointer, `db/migrations/0001_init.sql`'s claim schema - read both directly). Output: which fields changed, old value, new value, old/new source authority, old/new verification date. No I/O in this module - it takes two already-fetched claim-shaped objects and returns a diff structure, following the same "pure, DB-free" convention `app/planning/comparison.py` and `app/rules/eligibility.py` already establish (read one of them for the pattern).

`app/ai/what_changed.py` (new): a `what_changed` template, added to `app/ai/prompts.py`'s `TEMPLATE_REGISTRY` (by now including AI-18's `next_steps` entry too - read the file fresh, do not assume its pre-AI-18 shape) requiring `claim_id` (the **superseded** claim's id - `AskRequest.claim_id` already exists, read `app/ai/schemas.py`). Fetches the named claim and, if it has a `superseded_by` pointer, its successor; if either row is not readable under the caller's own RLS-equivalent access (re-check in code, the same defensive pattern `app/ai/retrieval.py` already uses - do not trust a caller-supplied id blindly), the answer is `not_available`, not an error. The two-pass model call (reuse `app.ai.pipeline.answer()`'s shape and `app.ai.guards`' validators - do not write a third parallel implementation) selects and verifies which diff lines are relevant to render; every rendered line is built **in code** from `claim_diff.py`'s own output, exactly the same "code renders, model only selects" rule every other Phase 1a template already follows.

Wire `what_changed` into `app/api/ask.py` (`ASK_TEMPLATES`, the route) the same additive-layer way `next_steps` was just wired by AI-18 - read that card's actual landed diff for the pattern to follow, do not reinvent it.

The plan-flag hook (surfacing "this saved plan may be affected" on `My Plan`) is explicitly **out of scope** for this card - it depends on `PUB-3`'s plan-flag mechanism, a Phase 1 card this session does not touch. This card only builds the `what_changed` answer itself, reachable via `/ask?template=what_changed&claim_id=...`.
