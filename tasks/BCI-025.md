# BCI-025 - Render AI answers on /ask/view: next_steps + what_changed resolution, plus the missing markup

Model tier: standard
Wave: P1a (post-close-out follow-up, 2026-09-23) - Phase 1a runs alongside Phase 1; this card touches no Phase 1 file
Worktree: phase1a/ui-12-ask-render

## The gap (verified by the lead directly against the merged code before this card was written)
`GET /ask` (the JSON route, `app/api/ask.py`) fully supports all four template outcomes - `ai_sentences`/`ai_citations` (basic templates), `next_step_actions` (AI-18's `next_steps`), and `what_changed_lines` (AI-19's `what_changed`) - all always-present-possibly-empty fields on `AskResponse`, all correctly resolved (including `next_steps`' `plan_id`-only path and `what_changed`'s `claim_id`-only path, both of which bypass the ordinary `pathway_id`/`career_id` resolution).

`GET /ask/view` (the HTML page, `app/web/ask_pages.py` + `app/web/templates/ask.html`) does **not** match this. Two separate, real gaps:

1. `ask_pages.py`'s `ask_page()` only ever calls `entity_kind_and_id(pathway_id, career_id)` to resolve the request, then `_pipeline_answer()` for whatever template was named - it never special-cases `next_steps` (which can be requested by `plan_id` alone, with no `pathway_id`/`career_id`) or `what_changed` (which is requested by `claim_id` alone) the way `app/api/ask.py`'s `ask()` route already does at its own lines ~673-737. A `plan_id`-only or `claim_id`-only request to `/ask/view` today hits the generic `entity_kind_and_id` path, which was never built for either shape, and likely mis-resolves or 404s instead of answering. Read `app/api/ask.py`'s `ask()` function directly for the exact resolution logic to mirror - do not re-derive it independently.
2. `app/web/templates/ask.html` has **no markup at all** for `ai_sentences`, `ai_citations`, `next_step_actions`, or `what_changed_lines` - none of the four are read anywhere in the template, even though `ai_sentences`/`ai_citations` are already threaded into the context (`ask_pages.py`'s existing `TemplateResponse` call). A student visiting this page today, even with AI on and a fully successful answer, sees only the deterministic fact cards - the AI's own contribution is invisible.

## What to build
`app/web/ask_pages.py`: extend `ask_page()` so `next_steps` and `what_changed` requests resolve correctly, mirroring `app/api/ask.py`'s own logic exactly (read it fresh, do not guess):
- `next_steps` with `plan_id` set and `pathway_id`/`career_id` both absent: resolve the plan's pathway through the existing plans API ownership check (same as the JSON route - a guest's or another student's plan id must 404, never leak another identity's actions).
- `what_changed` with `claim_id` set: bypass `entity_kind_and_id` entirely, resolve directly by claim id, exactly as the JSON route does.
- Thread `next_step_actions` and `what_changed_lines` into the template context alongside the existing `ai_sentences`/`ai_citations` keys, always present (possibly empty), same convention `app/api/ask.py` already established.

`app/web/templates/ask.html`: add rendering for all four, each shown **alongside** the fact cards, never instead of them, and only when non-empty:
- `ai_sentences` + `ai_citations`: one paragraph per sentence, each followed by its citation's source authority and link. `_trust_badge.html`'s `evidence_line()` macro expects a `verification_date` argument that neither `ai_citations`' dict shape (`record_id, field, value, source_authority, source_url, is_stale`) nor the citation shapes below carry - check whether passing `none` renders gracefully (read the macro's own default-argument handling) before reusing it as-is; if it does not degrade cleanly, build a smaller, local citation link (source authority + link, no date) rather than forcing an ill-fitting call. Match whichever pattern you choose consistently across all three citation kinds below.
- `next_step_actions`: a list, one item per action (`text`), each with its own citation link (`source_authority`/`source_url`, `claim_id` present but never rendered directly - it's an id, not a display value).
- `what_changed_lines`: a list, one item per line (`text`), each showing `attribute`, `old_value` and `new_value` are already available on the object if you want a more structured rendering than the pre-composed `text` alone - your call, document which you chose.

Every string in this template continues to go through `t()` for fixed labels (headings, etc.) - the AI-sourced text itself (`ai_sentences`/`next_step_actions[].text`/`what_changed_lines[].text`) is server-generated from claim data, never a translation-catalogue lookup, same as the existing fact-card values. **No input element of any kind** - this file's own header comment states the rule and a merged unit test greps for it; keep both true.

**Also fold in**: `askbcion.prompt.next_steps` and `askbcion.prompt.what_changed` are missing from `app/i18n/en.json`/`hi.json` entirely (confirmed - `cost_breakdown`/`pathway_overview`/`eligibility_gap` all have entries, these two don't) - `{{ t(prompt_key) }}` on this page's `<h1>` currently renders the bare key string for both templates. Add both keys, English text plus a draft Hindi translation, append-only, matching the existing three entries' style exactly. This is a tiny, directly-related fix, not a separate card.
