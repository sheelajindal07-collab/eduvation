## Scope (per Annex E.3)
"Published career record → explore → compare two options, on synthetic
fixtures." Exit proof required: real staging database and browser journey
pass; Annex D usability round 1 on the clickable prototype.

## Progress so far (2026-09-19)
- **Schema written**: `db/migrations/0001_init.sql` — `sources`,
  `careers`, `pathways`, `claims` (full provenance/status model per
  `docs/DATA.md`), `student_profiles`, `reviewers`. A DB trigger forbids
  ever publishing a synthetic-sourced claim (not just app-level policy).
- **RLS policies written**: world-readable public knowledge base,
  reviewer-only writes, strictly own-row `student_profiles`. Explicitly
  scoped as an M1 baseline — the stricter "author cannot approve their
  own claim" rule is deferred to M4 (noted inline in the migration).
- **Client wired**: `app/db/client.py` — anon client for guest reads,
  user-scoped client that carries the signed-in user's access token (the
  RLS-enforcement contract from `docs/SECURITY.md`). No owner/service-role
  path exists in application code at all.
- **RLS tests written for real**: `tests/db/test_rls.py` — guest /
  student A / student B / reviewer access matrix, 9 test cases. They
  create and tear down throwaway test users via the service-role key
  (test-only, never read by the app). Currently **skip with a printed
  reason** (verified: ran once, watched them error for a real reason —
  `pytestmark` in a conftest doesn't propagate — fixed with a
  `pytest_collection_modifyitems` hook, ran again, now skip correctly).

## Progress, continued (2026-09-19)
- **Comparison assembly** (`app/planning/comparison.py`): pure functions
  implementing `docs/DATA.md`'s trust-label mapping table exactly, plus

## Proposed breakdown
1. **Data foundation**: Supabase schema migration for `Source`, `Claim`,
   `Career`, `Pathway` (append-only migration file, per
   `docs/ARCHITECTURE.md`); RLS policies; restricted application role
   (never the owner/service role) — see `docs/SECURITY.md`.
2. **RLS tests** (`make test-db`): guest/student A/student B/reviewer ×
   read/write, run as the restricted role, not the DB owner.
3. **Explore screen**: list published Career records (synthetic fixtures
   seeded through the same publishing path a real record would use — no
   shortcut that lets fixtures skip maker-checker, even in dev).
4. **Compare screen**: two pathways side by side, fields per
   `docs/UI.md`'s comparison-field list (entry requirements, stages, time
   range, cost as three amounts, evidence with trust labels).
5. **Design track (parallel, Annex D.3)**: low-fidelity quick-start/
   explore/compare/plan flows; clickable prototype; usability round 1
   (5–8 participants) run *before* this slice's engines are considered
   done — not after.
